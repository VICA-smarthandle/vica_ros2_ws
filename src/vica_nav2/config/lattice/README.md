# Lattice 격자 — R 0.30 diff (2026-08-29 생성)

`SmacPlannerLattice` 가 쓰는 동작 조각(motion primitive) 세트다. planner 는 이
조각들을 이어붙여 경로를 만들므로, **여기 없는 동작은 planner 가 낼 수 없다.**

## 왜 만들었나

화장실 구간(`vica_map_0630`, 목표 3.5/5.4) 유턴이 항상 실패했다. 지도 실측으로
그 지점 여유가 0.70 m+ (**통로 폭 1.40 m**)이고 반경 1 m 안 free 셀의 92 % 가
제자리 회전 가능임을 확인했다. **좁아서 못 도는 게 아니었다.**

| 회전 방식 | 필요 폭 | 통로 1.40 m |
| --- | --- | --- |
| 제자리 회전 | 0.945 m | 가능 |
| 호 R 0.50 (설치본 격자) | 1.705 m | **불가** |
| 호 R 0.30 (이 격자) | **1.352 m** | 가능 |

Nav2 가 제공하는 격자는 `0.5m` 과 `1m` 두 가지뿐이고(1 m 는 nav2_backlog §11 에서
닫힘) 더 줄일 수 없다. Hybrid 로 바꾸면 반경을 파라미터로 지정할 수 있지만
**제자리 회전 primitive 가 없어** 좁은 곳에서 60초씩 헤맸다(2026-08-29 run1558).

이 격자는 **작은 호와 제자리 회전을 둘 다 갖는다.**

## 출처

```
생성기 : https://github.com/ros-navigation/navigation2
         nav2_smac_planner/lattice_primitives/  (브랜치 humble)
         2026-08-29 내려받음. 받은 파일:
           generate_motion_primitives.py · lattice_generator.py
           trajectory_generator.py · trajectory.py · helper.py
           constants.py · config.json · requirements.txt
의존성 : numpy, matplotlib, Rtree(pip --user 설치)
생성   : python3 generate_motion_primitives.py \
             --config config_r030_diff.json --output output_r030_diff.json
```

`config_r030_diff.json` 을 같은 폴더에 남겼다. 같은 격자를 다시 만들려면 위
생성기를 받아 그 config 로 돌리면 된다(2초 걸린다).

## 설치본(R 0.5)과 비교 — 무엇이 같고 무엇이 빠졌나

metadata 키와 primitive 필드는 **완전히 동일**하다. 값만 다르다.

| | R 0.5 (설치본) | **R 0.30 (이 격자)** |
| --- | --- | --- |
| 조각 수 | 112 | 88 |
| **제자리 회전** | **32** | **32 (동일)** |
| **직진** | **16** | **16 (동일)** |
| 곡선 | 64 | **40** |
| heading 별 구성(제자리/직진/곡선) | 16방향 모두 `2/1/4` | 축 4방향 `2/1/4`, **대각선 12방향 `2/1/2`** |
| 최대 조각 길이 | 0.649 m | 0.382 m |
| 유턴 필요폭 | 1.705 m | **1.352 m** |

**빠진 것은 대각선 방향의 곡선 2개씩뿐이다.** 격자 조각은 5 cm 눈금에서 정확히
끝나야 하는데, 반경이 작으면 곡선이 짧아져 눈금에 안 맞는 것이 생긴다. 대각선은
눈금 간격이 1.41 배라 더 안 맞는다.

다른 반경도 만들어 비교했다. **균등성과 유턴 폭은 맞바꿈 관계다.**

| R | 곡선 | heading 별 곡선 | 유턴폭 | 통로 1.40 m |
| --- | --- | --- | --- | --- |
| 0.30 | 40 | 2 또는 4 | **1.352** | 들어감 |
| 0.32 | 40 | 2 또는 4 | 1.386 | 들어감 |
| 0.35 | 32 | 전부 2 | 1.438 | 못 들어감 |
| 0.40 | 48 | 2/3/4 들쭉날쭉 | 1.525 | 못 들어감 |
| 0.45 | 64 | 전부 4 (균등) | 1.614 | 못 들어감 |
| 0.5 | 64 | 전부 4 (균등) | 1.705 | 못 들어감 |

**어느 반경에서도 제자리 회전 32개와 직진 16개는 그대로다.** 줄어드는 것은
곡선뿐이다. 0.30 을 고른 이유는 통로에 들어가는 둘(0.30·0.32) 중 여유가 더
크기 때문이다.

## 시도했다가 접은 것 — `num_of_headings` 32

방향을 촘촘히 나누면 눈금에 맞는 곡선이 늘어날까 싶어 만들어 봤다. **더 나빴다.**

| | heading 16 (채택) | heading 32 |
| --- | --- | --- |
| 조각 수 | 88 | **368** (4배, 탐색 부담) |
| 방향별 곡선 | 2 또는 4 | **0 인 방향이 4개** |

곡선이 아예 없는 방향이 생긴다. 이 축은 닫는다.

`grid_resolution` 을 0.025 로 낮추는 안도 있으나 costmap 해상도(0.05)와 달라져
권장되지 않는다.

## 되돌리는 법

`nav2_params.yaml` 의 `lattice_filepath` 를 아래로 되돌린다.

```
/opt/ros/humble/share/nav2_smac_planner/sample_primitives/5cm_resolution/0.5m_turning_radius/diff/output.json
```

## [실주행 미검증]

대각선 방향 곡선이 절반인 것이 주행에 어떤 영향을 주는지 확인되지 않았다.
경로가 덜 매끄럽거나 특정 방향에서 우회가 늘 수 있다. 조각 최대 길이도
0.649 → 0.382 m 로 짧아져 A* 가 더 많이 이어붙이므로 **planner 계산 시간을
함께 볼 것**(`Planner loop missed` 빈도).
